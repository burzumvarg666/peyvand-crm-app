## ایمیل واقعی کاربران

در صفحه زیر وضعیت سرویس SMTP را بررسی کنید:

https://supabase.com/dashboard/project/cvvqaftqzbuxctyabtgu/auth/smtp

سرویس پیش‌فرض Supabase فقط به اعضای مجاز تیم پروژه ایمیل می‌فرستد؛ برای کاربران دیگر، SMTP اختصاصی لازم است. حساب SMTP را در خود داشبورد تنظیم کنید و رمز آن را در کد یا چت منتشر نکنید. تأیید ایمیل را خاموش نکنید.

مرجع رسمی:
https://supabase.com/docs/guides/auth/auth-smtp

## روال کاربران

- ثبت‌نام: نام، ایمیل، رمز و تکرار رمز → تأیید ایمیل → ورود → ساخت فضای کاری شخصی یا پیوستن به دعوت موجود.
- دعوت: مدیر در اعضای تیم «ثبت و ارسال دعوت» را می‌زند. دعوت اول ذخیره می‌شود و بعد یک لینک یک‌بارمصرف ورود از Supabase درخواست می‌شود. شکست ارسال ایمیل، دعوت را پاک نمی‌کند.
- کاربر دعوت‌شده با همان ایمیل لینک را باز می‌کند، رمز انتخاب می‌کند و وارد تیم دعوت‌کننده می‌شود. اگر قبلاً عضو فضای کاری دیگری باشد، سیستم خودکار اطلاعات او را جابه‌جا نمی‌کند.
- بازیابی رمز: درخواست لینک → بازکردن لینک → انتخاب رمز جدید → ورود مجدد.
- وضعیت «درخواست ارسال پذیرفته شد» به معنای رسیدن ایمیل به Inbox نیست؛ Spam، محدودیت ارسال و گزارش SMTP هم باید بررسی شوند.

## آزمون فنی

```
npm run build
npm run test:auth
npm run test:auth-http
npm run test:crm
```

آزمون HTTP، مسیرهای واقعی Next.js را با سرویس محلی مستقل اجرا می‌کند؛ حساب یا ایمیل واقعی ایجاد نمی‌کند. آزمون واقعی تحویل ایمیل باید با یک نشانی آزمایشی مشخص و پس از تنظیم URL/SMTP انجام شود.
