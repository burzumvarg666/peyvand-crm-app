# نسخه ویندوز آماده شده است

راهنمای اجرای نسخه آفلاین در [desktop/README-WINDOWS.md](desktop/README-WINDOWS.md) قرار دارد. این نسخه از پایگاه داده محلی استفاده می‌کند. متن زیر مربوط به نسخه وب و وضعیت انتشار آن است.

# پیوند CRM

یک CRM فارسی و راست‌به‌چپ برای مشتریان، مخاطبان، فرصت‌های فروش و پیگیری‌ها. مقصد انتشار: Vercel. برنامه با Next.js 16، React 19 و Supabase Auth/PostgreSQL ساخته شده است.

## وضعیت تحویل

کد رابط، API، کنترل دسترسی و مهاجرت پایگاه داده آماده است. این بسته هنوز روی حساب Vercel منتشر نشده و به یک پروژه واقعی Supabase متصل نشده است. آزمون‌های زنده ورود، همکاری چندکاربره و سیاست‌های پایگاه داده باید پس از اتصال اجرا شوند. این تحویل نسخه اولیه عملیاتی است و نباید معادل CRM سازمانی با همه افزونه‌ها و آزمون‌های پذیرش تلقی شود.

## امکانات

- داشبورد محاسبه‌شده از رکوردها: تعداد مشتریان، ارزش فرصت‌های باز، فروش موفق، نرخ موفقیت.
- ثبت، ویرایش، حذف، جست‌وجو و فیلتر مشتریان و مخاطبان.
- پرونده مشتری با مخاطبان، فرصت‌ها، پیگیری‌ها و یادداشت‌های مرتبط.
- تابلوی فروش شش‌مرحله‌ای؛ تغییر مرحله از انتخابگر داخل کارت.
- مبلغ بر حسب تومان، تاریخ نمایشی شمسی، تاریخ ورودی میلادی.
- پیگیری‌ها با موعد، اولویت، مسئول، تکمیل و بازگشایی، فیلتر عقب‌افتاده.
- گزارش مراحل فروش و خروجی UTF-8 CSV با محافظت در برابر تزریق فرمول.
- ورود و ثبت‌نام ایمیلی؛ کوکی HttpOnly برای نشست و تمدید خودکار آن.
- ساخت فضای کاری و دعوت همکار با نقش کارشناس فروش یا مشاهده‌گر.
- مدیر اولیه فضای کاری دسترسی مدیریت دعوت‌ها دارد.
- جداسازی فضای کاری در PostgreSQL با RLS، ثبت تاریخچه تغییر رکورد و کنترل ویرایش هم‌زمان با شماره نسخه.
- حالت نمایشی با داده ساختگی در حافظه؛ با بازخوانی صفحه بازنشانی می‌شود. داده واقعی در localStorage ذخیره نمی‌شود.

## راه‌اندازی در Vercel

1. یک پروژه Supabase در حساب مالک برنامه ایجاد کنید.
2. فایل `database/001_crm.sql` را یک‌بار در SQL Editor پروژه تازه اجرا کنید. اجرای مهاجرت تراکنشی است؛ در صورت خطا ابتدا خطا را رفع کنید. روی پایگاه داده نامرتبط اجرا نکنید.
3. Email/Password و تأیید ایمیل را در Supabase Auth فعال نگه دارید. Site URL را آدرس نهایی Vercel قرار دهید و همان آدرس را در Redirect URLs اضافه کنید. برای تحویل مطمئن ایمیل‌های ثبت‌نام، SMTP پروژه را تنظیم کنید.
4. دو متغیر زیر را در تنظیمات Environment Variables پروژه Vercel وارد کنید:
   - `SUPABASE_URL`: آدرس پروژه Supabase، مانند `https://your-project.supabase.co`
   - `SUPABASE_ANON_KEY`: کلید publishable یا anon پروژه. **از service-role یا secret key استفاده نکنید**؛ مجوزهای RLS باید برقرار بمانند.
5. کد را در مخزن Git قرار دهید و در Vercel Import کنید. `vercel.json` از Next.js و دستور `npm run build:vercel` استفاده می‌کند. Node.js نسخه 22 یا جدیدتر انتخاب شود.
6. پس از انتشار، یک حساب ثبت‌نام کنید، ایمیل را تأیید کنید و وارد شوید. فضای کاری را بسازید؛ سازنده مدیر آن خواهد بود.
7. در «تیم و تنظیمات» ایمیل همکار را با نقش مناسب ثبت کنید. همکار باید با همان ایمیل تأییدشده وارد شود. برنامه ایمیل دعوت ارسال نمی‌کند؛ ارسال لینک به همکار جداگانه انجام می‌شود. دعوت‌ها با ورود یا تازه‌سازی اطلاعات پذیرفته می‌شوند.

برای انتشار با CLI در محیطی که قبلاً به حساب خودتان وارد شده‌اید:

```bash
npm ci --legacy-peer-deps
npx vercel
npx vercel --prod
```

هیچ رمز، توکن Vercel یا کلید محرمانه‌ای در این بسته وجود ندارد. اطلاعات محرمانه را داخل چت یا مخزن قرار ندهید.

## اجرای محلی

```bash
npm ci --legacy-peer-deps
cp .env.example .env.local
# متغیرهای Supabase را در .env.local تکمیل کنید.
npm run dev:vercel
```

بدون تنظیم Supabase، صفحه ورود راهنمای اتصال و دکمه ورود به نسخه نمایشی را نشان می‌دهد. حالت نمایشی جایگزین ذخیره اطلاعات واقعی نیست.

```bash
npm run build:vercel
npm run start:vercel
npm run test:crm
npm run test:http
```

پروژه از یک پوسته Vinext/Next.js آغاز شده و ابزارهای سازگار با آن نیز در بسته باقی مانده‌اند؛ برای مقصد Vercel از دستورهای دارای پسوند `:vercel` استفاده کنید. تنظیم `vercel.json` این انتخاب را خودکار انجام می‌دهد.

## معیار پذیرش پس از اتصال

- با دو حساب، دو فضای کاری مستقل بسازید. هیچ رکوردی بین آن‌ها قابل مشاهده یا تغییر نباشد؛ درخواست REST مستقیم با JWT حساب دوم نیز باید توسط RLS رد یا بدون نتیجه شود.
- یک مدیر و یک مشاهده‌گر در یک فضای کاری داشته باشید. مشاهده‌گر بتواند اطلاعات را ببیند و CSV بگیرد، اما درخواست مستقیم INSERT/UPDATE/DELETE او رد شود.
- دعوت یک ایمیل دیگر نباید برای حساب فعلی قابل پذیرش باشد؛ حساب دعوت‌شده باید ایمیل خود را تأیید کند.
- مشتری، مخاطب، فرصت و پیگیری بسازید، از حساب خارج شوید، روی دستگاه دیگر وارد شوید و ماندگاری داده را بررسی کنید.
- یک رکورد را در دو تب باز کنید. ویرایش تب دوم پس از ذخیره تب اول باید خطای تعارض بدهد؛ داده تب اول نباید بی‌صدا بازنویسی شود.
- حذف مشتری باید ارتباط رکوردهای وابسته را قطع کند و خود آن رکوردها را نگه دارد.
- خروج از حساب، تمدید نشست و خطای قطع ارتباط با پایگاه داده را آزمایش کنید.
- جریان ثبت‌نام و دریافت ایمیل را با SMTP واقعی و دامنه نهایی آزمایش کنید.

## محدودیت‌های این نسخه

- هر حساب فقط عضو یک فضای کاری است.
- تغییر نقش یا حذف عضو پذیرفته‌شده در رابط این نسخه وجود ندارد؛ مدیر می‌تواند دعوت‌های معلق را لغو کند. مدیریت اعضای موجود فعلاً باید توسط مالک پایگاه داده انجام شود.
- بازیابی رمز عبور در رابط، ورود دومرحله‌ای، پیوست، واردکردن گروهی CSV، صورتحساب، اتوماسیون، اتصال تلفن/پیامک/ایمیل و تقویم بیرونی پیاده‌سازی نشده‌اند.
- نمایش تابلوی فروش با انتخابگر مرحله است؛ کشیدن کارت‌ها با ماوس پیاده‌سازی نشده است.
- گزارش فروش کل دوره را پوشش می‌دهد؛ فروش موفق به معنای وصول وجه نیست.
- CSV خروجی گزارش است، نه پشتیبان کامل. پشتیبان‌گیری و بازیابی پایگاه داده را در سرویس Supabase تنظیم کنید.
- داده‌ها در صفحه به صورت دسته‌ای دریافت می‌شوند؛ این نسخه برای تیم کوچک است، نه میلیون‌ها رکورد. تاریخچه رابط ۱۰۰ تغییر آخر را نشان می‌دهد.
- آزمون بصری مرورگر و اتصال زنده Supabase/Vercel در این تحویل انجام نشده است.

## فایل‌های اصلی

- `app/page.tsx`: رابط کاربر، فرم‌ها و گردش کار
- `app/globals.css`: طراحی واکنش‌گرا و RTL
- `app/api/auth/route.ts`: ورود، ثبت‌نام و خروج
- `app/api/crm/route.ts`: عملیات فضای کاری و رکوردها
- `lib/server.ts`: نشست، درخواست امن و دسترسی Supabase
- `lib/crm.ts`: مدل، اعتبارسنجی، محاسبات و خروجی
- `lib/demo.ts`: داده نمایشی
- `database/001_crm.sql`: ساختار PostgreSQL، سیاست‌ها و توابع
- `vercel.json`: تنظیم انتشار Vercel
- `tests/crm.test.ts`: آزمون‌های محاسبات و اعتبارسنجی

## نتیجه بررسی در این تحویل

ساخت production و بررسی TypeScript موفق بوده‌اند. پنج آزمون محاسبات و اعتبارسنجی و بررسی HTTP صفحه، فایل‌های CSS/JS، دسترسی ناشناس، مبدأ درخواست، بدنه نامعتبر و نبود اتصال پایگاه داده موفق بوده‌اند. جزئیات در `VALIDATION.json` آمده است. آزمون HTTP از نسخه production و پایگاه داده تنظیم‌نشده استفاده می‌کند و آزمون RLS زنده محسوب نمی‌شود.
